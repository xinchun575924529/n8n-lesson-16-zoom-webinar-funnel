这条流水线干什么

落地页表单提交（含研讨会选择） → webhook 触发 n8n → Switch 按选择分流（新手场 / 专家场） → Zoom API 报名，拿回专属参会链接 → 联系人档案回写：链接 + 未来最近场时间 + 报名 tag（一次调用） → 营销提醒序列在数据就绪后才启动

你会学到

  • 「表单 → 分流 → 外部注册 → CRM 回写」四段式营销漏斗骨架
  • Switch v3.2 严格匹配的真实行为（大小写变体直接被拒）
  • 「取未来最近一场」表达式逐行拆解（5 种分支全部单测覆盖）
  • Zoom Webinar Registrants API 与 OAuth2 配置
  • 字段+tag+list 一体写入：规避「活动先发、数据后到」竞态

三大实锤坑（全部断言复现，课程里给修复版）

坑1 Switch 值不匹配→整条链静默丢弃 坑2 日期表达式无 NaN 守卫 坑3 报名体缺字段无守卫 坑4 手动审批无 join_url 坑5 硬编码 ID 替换清单 坑6 社区节点必须替身 坑7 跨节点引用断链

  • Zoom（付费 webinar）→ 本地 mock HTTP 服务真实 POST（教学）/ 腾讯会议 API（生产）
  • Switch 节点免费原样保留，骨架 100% 复用
